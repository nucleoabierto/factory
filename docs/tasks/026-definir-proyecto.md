Conversar con el usuario para entender qué quiere lograr con este proyecto: propósito, alcance, audiencia, casos de uso y criterios de éxito. La definición servirá de semilla para el documento de visión y el README.

## Entrada

- Decisiones de diseño documentadas en la tarea 025 como contexto de la forma actual del proyecto.
- `TODO.txt` y skills existentes como referencia del estado del proyecto.

## Resultado esperado

- Documento de definición del proyecto en `docs/` con el contenido acordado con el usuario, puesto a consideración para aprobación antes de finalizar.

## Criterios de calidad

- Recoge la visión del usuario mediante preguntas dirigidas.
- Cubre: propósito, alcance, audiencia, casos de uso y criterios de éxito.
- El borrador se presenta al usuario para aprobación antes de finalizar.
- Pasa revisión de redacción y pulido mecánico.

## Procedimiento sugerido

1. Hacer al usuario preguntas dirigidas sobre propósito, alcance, audiencia, casos de uso y criterios de éxito.
2. Redactar un borrador de definición con las respuestas.
3. Aplicar revisión de redacción y pulido mecánico.
4. Presentar al usuario para aprobación.

## Notas

- Las preguntas deben ser abiertas pero enfocadas, para evitar respuestas vagas.
